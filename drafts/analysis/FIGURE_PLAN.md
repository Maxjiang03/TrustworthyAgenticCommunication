### 0.3 D4 — false_block causation: the monitor was GENUINELY ABSENT

**Question.** For the four `false_block` cells (B3 and B3⁺ on `cf-f4-declassified`
and `cf-f5-approved`, all `monitor_attached=False` [M]): was the monitor genuinely
absent, or only declared absent?

**Answer: genuinely absent.** Four-link evidence chain, all `[M]`:

1. **Single origin.** `src/harness/campaign_driver.py:242-258` — one loop variable
   `configured` per pass feeds BOTH `_factories(monitor_attached=configured)` (arm
   provisioning) and `run_campaign(monitor_attached=configured)` (the recorded
   declaration), inside a single call expression. The recorded value and the
   provisioning value cannot diverge without editing that expression.
2. **Provisioning.** `campaign_driver.py:134-136` injects the value into the setup
   kwargs; `src/harness/runner.py:386` (b3_setup) and `:541` (b2_setup) bake
   `"monitor_attached"` into the provisioning material; one `b3_setup` dict
   provisions B-cap, B3, and B3⁺ alike (`campaign_driver.py:164-166`).
3. **Object graph.** `src/sut/baselines/b3.py:108-117` — `monitor =
   ContextApprovalMonitor(...) if setup.get("monitor_attached", True) else None`.
   Under `False`, no monitor object is ever constructed; the decision path receives
   `monitor=None`.
4. **Behaviour.** `src/sut/authz/capability_path.py:842-848` — with `self._monitor
   is None`, `context_policy_ok` refuses presented label assertions fail-closed;
   the mapped reason code is `b3_context_policy` (`capability_path.py:181`). All
   four false_block cells carry exactly `b3_context_policy` with
   `observed_forwarded=false, effect_count=0` [M], and the SAME four cells under
   `monitor_attached=True` forwarded with reason `b3_admitted` [M]. A
   secretly-attached monitor would have verified the controls' valid artifacts and
   forwarded — behaviourally incompatible with the observed blocks.

**Verdict per the ruling:** the four cells stand as a **G-15(ii) fail-closed
RESULT**, presented as planned.

**Caveats carried, not hidden.** (a) No independent post-hoc cross-check compares
the recorded declaration against the constructed arm state; the guarantee is
constructional (single origin) plus behavioural (reason codes and the
configuration contrast). (b) The setup defaults differ — `b3_setup` defaults
